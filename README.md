## 💫 What you'll find inside

### 🏠 Your Dashboard
A reading life at a glance: your **Today's Pick**, the book you're mid-way through
(with "~hours left at your pace"), your streak, goal progress, and activity — all
from your real reading, nothing fabricated.

### 🔍 Discover
Search *any* book (not just our list) with live results and real covers, filter by
your favorite genres with one tap, browse **Trending Now from the web**, and get
AI picks ranked for you — with a human-readable **why** on every card.

### 📖 Your Shelf
Start a book, log pages with one tap (using *your own* average pace), or just answer
**"I'm on page 143"** — the shelf does the arithmetic. Finish with a little
celebration and keep notes. Progress is calculated from the book's **real page
count**, so "84 pages left" and "~2 sessions" are true, not guesses.

### ❤️ Wishlist
One tap saves a book for later. When you're ready, **Start Reading** moves it
straight onto your shelf — saved-for-later becomes read-today.

### 🤖 The AI Reading Companion
Press `⌘J` and talk like a human:

> *"Something like my last thriller, but with a happier ending."*

It answers with real books, real covers, and a **reason** for each pick. It learns
your genres, your pace, your streak, and what you just finished — and it *never
repeats itself*.

### ⌘K Anything
One shortcut for the whole app. `⌘K` opens a command palette that **does things**,
not just searches: log today's pages, ask the companion, switch theme, jump to any
book (live web search included).

### 🩹 Streaks that forgive
Miss a day after a real run and you get **one honest repair** — "Restore my streak" —
or "Start fresh", which is remembered so we never nag. The repair never invents
pages read, so your analytics stay true.

### 📊 Reading Analytics
Streaks, pages this month, books finished, top genres — plus a warm **AI reading
insight** that reflects on your real progress. Your growth, visible.

### 📰 Book News
Real headlines from **The Guardian, The New York Times, BBC News and Literary Hub**,
merged and sorted newest-first. If every feed is unreachable the page says so — it
never invents a story.

## 🧠 Built the way readers think

GoodBooks isn't just a list of features — it's designed around the psychology of
*sticking with reading*:

- **Micro-commitments** — logging pages is one tap, and it uses *your* average, so the habit is effortless to keep.
- **Goal-gradient effect** — every progress bar, "X% complete", and "X left" makes the finish line feel nearer, pulling you forward.
- **Identity** — see your reading persona ("Immersive Reader", "Binge Reader"…) and let it motivate you.
- **Variable reward** — a new Today's Pick every day and fresh AI suggestions keep discovery delightful, not repetitive.
- **Loss aversion, reversed** — your streak and progress are *yours*; losing them feels worse than skipping feels good. So a missed day gets **one honest repair**, not a shame spiral.
- **Trust** — every filter works, every button does something, every number is real. Nothing fabricated, ever.

## 🔒 Your reading stays yours

- Your taste profile and shelf live **on your device** — the app is local-first.
- When a database is configured, reading *events* (a random device id, book id, pages,
  progress) are mirrored so your progress can survive a device change. No email, no name,
  no fingerprints, and **no public read path** — see [docs/DATA_LAYER.md](docs/DATA_LAYER.md).
- No tracking pixels, no spam, no credit card, no dark patterns.
- Export your whole reading library anytime — it's your data.
- Optional sync keeps things in your control.

## 🛠️ For developers & contributors

GoodBooks is a modern, fully-tested frontend with a serverless edge backend
(Cloudflare Pages Functions) — no heavy ML server required.

| Stack | |
|---|---|
| Frontend | React 18 · TypeScript (strict) · Vite 5 · Tailwind CSS · Framer Motion |
| State | Redux Toolkit (8 slices) + localStorage persistence |
| Backend | Cloudflare Pages Functions (`/api/*`) — recommendations, AI chat, live web catalog |
| AI | OpenAI-compatible chat (MiniMax-M2), grounded in real reader data |
| Data | Supabase-ready schema + Open Library / Google Books live catalog |
| Tests | 100+ Vitest tests passing · `tsc` clean · ESLint 0 errors |

```bash
npm install
npm run dev        # local dev → http://localhost:3000
npm test           # one-shot test run
npm run build      # production build
```

Deployment is one command to Cloudflare Pages (`npm run deploy`), or automatic via
the included GitHub Actions workflow.

### Project structure

- `src/components/` — React feature components (Dashboard, Discover, AI, Shelf…)
- `src/stores/` — Redux slices (user, reading, books, ai, analytics…) + reading sync middleware
- `src/utils/` — recommendation engine, personalization, shared book filters, chat context
- `functions/api/` — serverless edge API (catalog, search, trending, reading events, AI chat/insight)
- `dashboard/css/materials.css` — premium material/elevation/motion layer
- `tests/` — unit + component tests
- `docs/` — architecture, runbook, data layer, **UX research & rationale** (`docs/UX_PREMIUM_UPGRADE.md`)

Contributing conventions: Chain-of-Thought comments, JSDoc on every export,

### CI/CD

| Workflow | Trigger | What it does |
|---|---|---|
| `CI` | every pull request | `npm ci` → type-check → lint → test → build → purge → **build-output assertions**. Required to merge. |
| `Deploy to Cloudflare Pages` | push to `main`, manual | the same gates, then `wrangler pages deploy dist`, then a **live smoke test**: app shell `200` + `#root`, `/api/books` returns JSON `200`, custom domain serves. |
| Dependabot | weekly (Mon 06:00 IST) | grouped npm + GitHub Actions updates, each verified by `CI / verify`. |

`main` is protected: `verify` must pass, force-pushes and deletions are blocked, and
conversation resolution is required. A broken branch can no longer reach production —
the gate that proved this caught a real `npm ci` peer conflict within minutes of being
switched on.

**Linting runs on ESLint 9 (flat config).** `eslint.config.js` replaced `.eslintrc.json` when
the project moved to ESLint 9.39 + `typescript-eslint` 8 + `eslint-plugin-react-refresh` 0.5.
The rule set is unchanged — the migration moved the toolchain, not the standards (same 68
warnings, 0 errors, before and after). Two consequences worth knowing:

- Flat config does **not** skip dotfiles, so macOS `._*` sidecars are ignored explicitly and
  `scripts/purge-apple-double.cjs` now cleans `src/`, `tests/`, `public/`, `.github/` and
  `dashboard/` too — otherwise a macOS checkout fails lint with "Invalid character".
- `eslint` stays on 9.x and `eslint-plugin-react` on 7.x: 7.37 is the last published major and
  peers on `eslint ^9.7`, so ESLint 10 waits for a react-plugin release.

**Deferred migration (deliberately not automated).** Dependabot ignores majors for
**Vite 5 → 8 / Vitest 0.34 → 5** with `@vitejs/plugin-react` 6 and `@vitest/ui` 5 — a partial
bump cannot install. It is a planned pass, not weekly maintenance. Everything else updates
automatically.

**Codacy requires a one-time owner action.** The `Codacy Static Code Analysis` check reports
`ACTION_REQUIRED` (not a code failure) until the repository is authorised:
1. Sign in at [app.codacy.com](https://app.codacy.com) with the GitHub account that owns the repo.
2. **Add repository** → `kakashi3lite/GoodBooksRecommender` → grant access.
3. Organisation settings → **Integrations → GitHub** → enable the Codacy app for the repo so it
   can post status checks (this is what clears `ACTION_REQUIRED`).
4. Optional: add `CODACY_PROJECT_TOKEN` as a repo secret to upload coverage from `CI / verify`.
Until then Codacy is advisory only — `verify` is the required gate, so merges are not blocked.
